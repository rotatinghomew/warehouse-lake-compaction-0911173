# 观看文件与读者

一个事件只属于一次逻辑上传，文件路径是存储位置而不是事件身份。文件不可原地改变；目录中存在文件不表示它已经对某个快照可见。查询由清单引用确定，不通过列目录猜测表状态。

## 表版本与有效期

- 每个快照在创建时绑定显式的 `expires_at`（UTC 时刻），默认有效期 24 小时，可用 `renew` 正常续期。有效期判断只使用调用者可观察的当前时刻，不依赖任何进程是否仍在运行。
- 有效期内，快照固定的文件集合必须可完整读取，包括导出延迟开始、重复打开同一文件的情况；整理改变物理布局也不影响旧版本读取。
- 到期读取得到明确的 `SnapshotExpired` 错误；引用从未存在得到 `SnapshotMissing`。两者都不同于数据为空——空集合（例如日期过滤无命中）正常返回 `[]`。
- 到期快照不再构成空间占用依据，其引用的文件在没有其他引用时可被回收，空间不会被无限拖住。

## 在线整理

- 整理只改变文件布局：同一业务日期的多个小 Parquet 合并为较大文件，发布前以事件多重集与内容校验和核对，业务记录不增不减。
- 整理期间的新上传写入独立的不可变文件，发布事务只重新指向当时规划的输入集合，不会盖掉新上传；新上传出现在之后的快照里。
- 整理任务是可恢复状态机（`planning → writing → ready → published`，异常置 `failed`）。输出文件在写入前先登记进 `physical_files`，因此在写完新文件后、切换清单时或开始删除后退出，都能依据「登记表 vs 真实文件」恢复到可解释状态，不依赖文件修改时间。
- 全局整理锁配 fencing 令牌：两个整理者并发时只有一个能生效；锁心跳超时后可被接管，被接管者的旧令牌在后续任何写入或清单切换处失效。重试同一批输入复用已发布任务，同一批记录不会出现两遍。

## 空间回收

回收只认真实的表版本对应关系。一个物理文件可删除，当且仅当它已登记在 `physical_files` 中，且同时不被以下三者引用：

1. 当前上传清单（`uploads.path`，含整理期间的新上传）；
2. 任何未到期快照固定的文件集合；
3. 未结束整理任务预登记的输出文件。

删除前再次核对文件内容 SHA256 与登记值；磁盘上未登记的 Parquet 只报告不删除。业务日期查询仍为精确过滤，追加入口行为不变。
